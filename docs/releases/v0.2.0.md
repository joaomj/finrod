# Finrod v0.2.0

Finrod is now a **browser-only AI chat companion**. The browser runs conversation
and research logic and stores chats locally. Static hosting distributes
application files only. No central Finrod account or conversation backend is required.

This is an early browser release, not a claim of complete phone acceptance.

## Included

- Dark chat interface with streamed replies, safe Markdown, source links, and compact research activity.
- Separate chats with sequential IDs, generated titles, and local answer feedback.
- IndexedDB persistence, earlier browser history migration, and all-chat export/restore.
- Direct OpenRouter inference with `anthropic/claude-haiku-5.5` as the initial model.
- Native Exa MCP search and page retrieval, with optional personal Exa credentials.
- Visible rate-limit failures, interruption recovery without replay, and blocked continuation after storage failures.
- Separate saved keys, explicit removal controls, and redaction of configured credentials.
- Browser build, integration checks, dependency audit, and CodeQL release gates.

## Removed

The server runtime, bot integration, Linux installer, service template, server-only
dependencies, and obsolete tests are removed. This release does not provide those
installation or delivery paths. Pi Durable and SQLite remain only for earlier
browser history migration and its verification, not normal chat execution.

## Verification

Browser typechecking, bundling, and all three controlled browser scenarios passed.
The scenarios cover migration, research, separate context, titles, reopening,
export/restore, writer locking, interrupted-tool recovery, storage/provider
failures, and credential handling. The Exa rate-limit regression failed before
the repair for the intended reason and passed afterward.

The merged browser-only revision passed GitHub CI, including the dependency audit
and CodeQL. Publication of this release requires the tag's own gates to pass.

The user reports successful iPhone/Brave conversations, reopening, live research
with a personal Exa key, and saved-key restoration. These observations do not
close the complete phone release gate. See [Validation](../retired/VALIDATION.md).

## Privacy and limits

History, saved keys, and backups are not application-encrypted. OpenRouter and
its inference provider receive submitted model context. Exa receives research
queries and requested URLs. The browser profile, host, and application updates
remain trust boundaries.

There is no automatic synchronization, voice input, imported-source retrieval,
or complete execution-log export. Encryption and complete log export remain planned.

Remaining phone checks include phone-only setup, export/restore, interruption,
the second user's Chrome phone, actual keyboard behavior, abrupt termination,
and large-history performance. Desktop checks do not prove phone compatibility.

## Upgrade and distribution

Export current chats before changing the application or storage format. Use the
same website origin when returning; another origin has independent history and
credentials. Earlier browser histories migrate without clearing site data.

Build with `npm run build` and publish the complete `web-dist/` directory on an
HTTPS static host. Publishing requires separate approval. The release workflow
does not deploy to Cloudflare, change the VPS, or modify local browser data.
