# Finrod v0.1.0

The first release records the working **self-hosted, one-user-per-bot-instance** architecture,
validated locally and deployed to a Contabo VPS.

## Included

- Owner-only private Telegram conversation powered by Pi Durable and SQLite.
- Text and voice input, with configurable transcription and a Portuguese language hint.
- Bounded recovery from interrupted voice downloads.
- Restricted Exa search and fetch, plus explicitly saved Markdown topics.
- Persistent per-reply feedback and a private metadata exporter.
- Guided Linux installation, private configuration, and a non-root systemd user service.
- Documented backup, migration, validation, and Mermaid architecture overview.
- Tag-triggered build, test, and security gates before GitHub release publication;
  automatic release-note generation and no deployment to user instances.

## Verified

The isolated installer test exercised first installation and a preserving rerun.
On the VPS, the actual installer installed a compatible Node runtime, built the
application, and started the service. A stopped-service archive was restored with
integrity and record-count checks. New text, feedback, and voice requests succeeded,
and a new summary recalled conversation from before migration. The local instance
was stopped and disabled before the VPS instance started.

## Limits

- One authorized Telegram user per bot instance. This is not the multi-user release.
- Stored conversation and topic content has no application-layer encryption;
  server administrators can access it.
- Interrupted-turn recovery, remaining topic operations, and changed feedback
  still need live validation. Source correctness is not established by citations alone.
- VPS reboot startup, privileged OS-package installation, and the arm64 installer
  path have not been exercised.

## Next direction

`docs/ROADMAP.md` proposes v1: one bot serving hundreds of authorized users with
isolated history, knowledge, voice, and feedback; fair scheduling; encrypted
persistence; and explicit key-management, privacy, recovery, and capacity gates.
These are future requirements for operator-owned instances, not a centrally
hosted Finrod service or features and guarantees of v0.1.0.
